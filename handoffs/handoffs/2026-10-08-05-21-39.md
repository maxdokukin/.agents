## 6. Design decisions

- **Decision:** A new copy starts with zero handoff entries.
  **Why:** The reference's entries are its own history. A project should not inherit them.
  **Alternatives rejected:** Shipping the sample entries and letting the human delete them.
- **Decision:** setup.sh never overwrites an existing .agents/ and points at check.sh instead.
  **Why:** An existing folder may hold real handoffs; overwriting is destructive (R-23).
  **Alternatives rejected:** A --force flag.
- **Decision:** check.sh mirrors the seven validation checks of xewe_handoff plus structural
  checks, and is read-only.
  **Why:** One set of invariants, checked the same way everywhere; repairs stay human (R-11).
  **Alternatives rejected:** A check that auto-regenerates HANDOFF.md.
- **Decision (rule edit under R-18):** R-05 gained one exception, on the human instruction
  quoted in section 2. Setup cannot initialize handoffs/ otherwise.
- **Decision:** The `<project>` placeholder is a warning in check.sh, not a failure.
  **Why:** The reference itself legitimately carries it; only copies should not.

## 7. Philosophical choices

- Setup is a script, not prose. Deterministic steps belong in code so every copy is identical.
- A tool that refuses is safer than one that asks for a flag.
