## 6. Design decisions

- **Decision:** Skills live at `skills/<name>/SKILL.md` and are discovered from frontmatter; the router is gone.
  **Why:** Every host tool (Claude Code personal, project, and plugin skills) uses this exact shape and builds its own index from frontmatter. A router was a second source of truth that no tool read, and `skill/SKILL.md` looked like a broken skill to any scanner. A skill folder now copies between `.agents/skills/` and `~/.claude/skills/` unchanged.
  **Alternatives rejected:** Keeping the router as `skills/SKILL.md` (drift stays possible, loose file in a scanned folder).
- **Decision:** Version 1.1, not 2.0, by the human's choice.
  **Why:** Treated as a layout change; nothing had been installed anywhere at 1.0.
  **Alternatives rejected:** 2.0 (fixed names in R-13 changed, which is what a major bump is for).
- **Decision (R-03 deviation, human instruction):** Edited RULES.md (R-15), AGENTS.md (P-05), README.md (P-01, P-05), check.sh and setup.sh (the human's earlier "stop touching code" instruction), and renamed a top-level item (R-13). Instruction: "lets rework our .agents to `~/.claude/skills/<name>/SKILL.md` skills format" with the answers "Drop it" and "WAX 1.1".
  **Why:** Each file names the fixed path or rule being changed; the scripts could not keep working otherwise. Script edits were kept to the path strings and the removed registration check.
  **Alternatives rejected:** none
- **Proposal (P-10), install flow for the future `wax` repo:** a public repo with `skills/wax_agents/SKILL.md` (install, upgrade, check) and `skills/wax_handoff/SKILL.md` (a copy that defers to the project's own), an optional `.claude-plugin/plugin.json`, and no bundled tree. One-time install: clone under ~/.claude and symlink each skill into ~/.claude/skills (path 1), or `claude plugin marketplace add` plus `claude plugin install` once a marketplace manifest exists (path 2). Per project, `wax_agents` detects an existing `.agents/` (absent, WAX with version, XAW era, foreign, failing check), clones `maxdokukin/.agents` at a tag into `.agents` and strips `.git`, fills the project name, walks PREFERENCES.md, offers a pointer block for the root CLAUDE.md and AGENTS.md, runs check.sh, and tells the human to start a session with pickup. Prerequisite: tag the public repo. This answers one open question: the public `.agents` repo stays, as the tree the skill fetches.
