## 6. Design decisions

- **Decision:** The genesis entry is a checked-in file in the public repository; setup.sh copies handoffs as shipped and only fills the project name.
  **Why:** The human rejected script machinery for seeding and publishing. A checked-in file needs no code and is exactly what a bare clone gets.
  **Alternatives rejected:** Seeding from an asset via lib.sh (previous entry, rolled back); zero-entry state (would lose the exploration instruction).
- **Decision:** Keeping the public repository in sync with this tree is a manual step: rsync everything except .git and handoff entries, then edit the genesis head by hand if the format changed.
  **Why:** publish.sh was removed on the human's instruction.
  **Alternatives rejected:** none kept.
- **Decision:** `Session` is a section 1 key with `<host> <id>`; `Resume` is a HANDOFF.md head key with the paste-ready command. Both allow `none` and `unknown`.
  **Why:** The human asked for identity, session id, and a copy-paste resume line. Allowing `unknown` keeps non-Claude hosts valid; `none` fits the genesis entry.
  **Alternatives rejected:** Resume as the default way to start a session (it bypasses pickup and only works on the machine that ran the transcript).
- **Decision (R-03 deviation, human instruction):** Edited the template (R-07), RULES.md (R-15), README.md (P-01, P-05), and the public clone's handoffs by hand (R-04, P-02). Instruction: "record the identity and session id of the agent that wrote the handoff, HANDOFF.md points to the last identity as well in a form of copy past to resume that session" and "rollback whatever u changes".
  **Why:** Each is required by the requested format change or by the rollback.
  **Alternatives rejected:** none
- **Decision:** check.sh still checks six HANDOFF.md keys, not the new seventh.
  **Why:** The human asked for pre-session script bytes; the skill's own validate step covers `Resume`.
  **Alternatives rejected:** Adding one word to the check.sh key loop (a code change the human did not ask for).
- **Proposal (P-10):** When the human next allows a script change, add `Resume` to the HANDOFF.md key loop in check.sh so both validators agree.

## 7. Philosophical choices

- Less machinery beats more: a checked-in file that needs no code wins over a script that generates it.
- The handoff is the resume mechanism; a transcript id is a courtesy for the same machine, not a dependency.
