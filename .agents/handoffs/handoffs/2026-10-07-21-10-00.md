## 6. Design decisions

- **Decision:** All timestamps are UTC; entry filenames are `yyyy-mm-dd-hh-mm-ss.md`.
  **Why:** Sorts correctly as plain text, so HEAD is simply the greatest filename, and UTC
  removes ambiguity between machines.
  **Alternatives rejected:** ISO 8601 with `T` and `:` (awkward in filenames); local time.
- **Decision:** HANDOFF.md is a head node that holds only HEAD, directory status, and an index.
  **Why:** The same principle as skill/SKILL.md: routers point, content lives one level down.
  A small file is cheap to validate and cheap to read on every session start.
  **Alternatives rejected:** Appending the latest entry's summary into HANDOFF.md.
- **Decision:** Section 9 "Exit point" has exactly four fixed keys.
  **Why:** The pickup procedure can consume it mechanically and quote it verbatim.
  **Alternatives rejected:** Free-form "next steps" prose.
- **Decision:** On any HANDOFF.md inconsistency the skill stops and reports; it never repairs.
  **Why:** A silently repaired head hides lost or duplicated work. A human can fix it in a
  minute with full information.
  **Alternatives rejected:** Auto-regenerating HANDOFF.md from the directory listing.
- **Decision:** Agents are forbidden from reading README.md.
  **Why:** It holds rationale and history for humans. Loading it costs context and risks it
  contradicting the agent-facing files, which are the only source of truth for agents.
  **Alternatives rejected:** A single combined document.
- **Decision:** skill_2 keeps its placeholder name and is a reference skill only.
  **Why:** Its job is to show the shape of a skill. A real name would invite running it.
  **Alternatives rejected:** A second working skill (for example a skill scaffolder).
- **Decision:** Every path inside `.agents/` files is relative to `.agents/`.
  **Why:** The folder must stay copyable between projects.
  **Alternatives rejected:** Paths relative to each file's own directory.
- **Decision (bootstrap note):** This session wrote RULES.md, AGENTS.md and README.md directly,
  which R-18 forbids for later sessions. The rules did not exist until this session wrote them;
  the human's instruction quoted in section 2 covers this. R-18 applies from this entry on.

## 7. Philosophical choices

- Handoffs are the project's memory. Chat history is not. If it is not in a handoff, the next
  session does not know it.
- Routers never hold content. HANDOFF.md and SKILL.md point; entries and skills carry.
- Rules are absolute so they can be cited, not debated. Flexibility lives in R-04 (human
  precedence) and R-24 (proposals), nowhere else.
- Human documentation and agent documentation are separate files with separate audiences.
- An agent that stops on inconsistency is more useful than one that guesses.
